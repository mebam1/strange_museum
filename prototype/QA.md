# 프로토타입 검증 기록

2026-11-16부터의 검증 기록이다. 텍스트 엔진과 기본 수치를 먼저 검증한 뒤 같은 엔진에 그래픽 UI를 연결했다. **최신 기능 검증은 맨 아래의 2026-11-17 규칙 v5 절**이다. v3와 이전 절의 브라우저 조작·HTTP 확인은 당시 기록이며 v4의 시각 검증 통과를 뜻하지 않는다. 이전 절의 고레벨·평가 기준·자동 승률은 당시 버전의 기록이며 현재 수치로 읽지 않는다.

## 규칙과 밸런스

- Node 기본 테스트 러너: 규칙 32개 + 화폐 소수점 경계 2개, 총 34개 통과.
- 최종 수치: 훈련 150런과 분리된 검증 300런, 합계 450런. 상세 결과와 재현 명령은 [BALANCE.md](BALANCE.md).
- 통제된 겹침 기대값: 조건별 7,776개 물리적 주사위 면 조합 완전 열거. 실제 런의 성능이나 인간 플레이 결과와 구분한다.
- 텍스트 CLI: 보관·리롤·미리보기·제출·상점·거절·면 개조·판매·다음 관객의 실제 입력 경로 확인.

## 브라우저에서 직접 확인한 조작

로컬 서버 HTTP 200을 확인하고 기본 데스크톱 창과 모바일 폭에서 실제 화면을 조작했다. 아래는 기능 QA이며, 인간의 재미·학습 난이도를 측정한 플레이테스트가 아니다.

- 주사위 보관, 보관한 눈 유지, 공유 리롤 차감, 제출 후 무료 새 주사위와 보관 해제.
- 제출 미리보기와 실제 감동, BFS 표시, 발동 완료 유물의 검정 덮개, 연출 건너뛰기.
- 무료 상자 열기, 조각과 유물 각각 선택, 기존 유물 아래 조각 겹치기.
- 유물이 이미 있는 위치의 배치 거절과 선택 유지, 빈 칸에 즉시 배치.
- 유료 유물 구매, 유물 이동, 판매가 10% 수입, 소수 판매 수입을 이용한 조각 구매.
- 조각 90도 회전과 연결 배치.
- 주사위의 특정 면을 변경하고 다음 관객의 눈 확률 표시가 1/6에서 2/6으로 바뀌는 것 확인.
- 새로고침 후 돈·배치·진행 복원, 새 런 시작.
- 낮은 레벨 조각만 강화하는 부족 충전 사례: Lv.6과 Lv.1이 겹친 칸의 붓 충전 1이 Lv.1 조각만 Lv.2로 올린 후 사라짐. 별도의 붓은 원래 조각을 Lv.7로 올림. 해당 제출 점수는 강화 전 횟수를 사용함.
- 평가 담당자의 세 제출 합계가 210, 기준이 210일 때 통과. 이후 2주차 일반 관객 기준이 144가 되는 것 확인.
- 실행 중 브라우저 경고·오류 로그 없음.

작은 데스크톱 창에서 주사위 조작판이 보드를 덮는 문제를 수정했다. 보드는 화면 높이에 맞추고 양옆 상세 패널을 스크롤하도록 했다. 모바일 폭에서 문서 가로 넘침이 없고 주사위 조작 버튼이 작동하는 것을 확인했다. 임시 뷰포트 설정은 검증 후 해제했다.

## 표시상의 선택

동일한 원천에서 반복하는 독립 연쇄는 대표 한 번을 보여주고 `독립 연쇄 ×N`을 표시한다. 계산은 모든 반복을 포함한다. 소진 유물은 자기 마지막 연쇄가 끝난 뒤 화면에서도 제거한다. 제출 중 판정에 쓰이는 배치와 보정은 고정되어 있다.

## 남은 검증 범위

사람의 장시간 플레이와 다양한 겹침 전략의 성능은 아직 검증하지 않았다. 8주 종료·승패는 엔진 테스트와 자동 런에서 확인했으며, 브라우저 수동 조작으로는 1주를 완주하고 2주차 진입까지 확인했다.

## 배포와 단일 HTML

비공개 사이트 등록은 완료했지만 소스 저장소 호스트의 DNS 해석이 실패해 온라인 배포는 완료하지 못했다. 샌드박스 밖 터미널로 인증 토큰을 전달하는 경로는 자동 승인 검토에서 보안 경계 우회로 거절되었으며 사용하지 않았다.

대신 `build-standalone.mjs`로 동일한 모듈을 `dist/play.html` 하나에 묶었다. JavaScript 구문, 원본과 묶인 엔진의 실제 진행 상태 일치, 외부 스크립트·스타일 요청이 없음을 확인했다. 브라우저 자동화 정책이 `file:` URL을 허용하지 않아 **직접 파일을 여는 경로의 브라우저 검증은 하지 못했다**. 위 기능 QA는 동일한 원본 게임을 로컬 HTTP 서버에서 실행해 수행한 결과다. 정책을 우회하는 다른 브라우저 경로는 시도하지 않았다.

## 2026-11-17: 전시 도선·겹빛 렌즈와 평가 기준 조정 — 규칙 v3

- 메아리석·공명 종을 전시 도선·겹빛 렌즈로 교체했다. 최종 카탈로그의 일반 기준 70, 평가 기준 150, 주간 배율 1.46, 보스 직후 배율 1.30을 적용하고 규칙·화폐 테스트 **49/49개를 통과**했다.
- 새 테스트는 효과 종류와 무관한 도선 수신, 렌즈의 자기 눈 조건과 구성 조각 수 보상, 상시 보정 순서, 도선↔렌즈 순환·합류의 BFS 1회 참여, 독립 원천 반복, 무대상 붓 제외, 미리보기 순수성을 확인한다.
- 미완료 구 저장의 유물·상품 변환, 완료 구 저장의 이름·고레벨·점수·관람 기록·기록된 평가 기준 보존도 테스트했다. 새 슬롯은 `strange-museum-run-v3`이며 v2·v1 원본을 덮어쓰지 않는다.
- 텍스트 CLI에서 시드 42로 새 카탈로그, 미리보기, 3회 제출, 무료 렌즈 배치, 도선 이동, 주사위 면 개조, 보상 거절, 다음 관객 진행을 실제 명령 경로로 확인했다.
- 로컬 HTTP UI에서 도선이 동전과 거울의 발동을 모두 받는 것을 확인했다. 무료 5눈 도미노를 시작 조각에 겹치고 렌즈를 배치하여 `[1,5]`, 레벨 합 `2+1=3`, **1회 보상 +12**를 확인했다. 조건이 맞지 않을 때는 0회, 리롤로 조건을 채우면 거울의 두 독립 연쇄를 받아 2회 발동했다.

- `dist/play.html`을 재생성했다. 번들 구문 검사, 외부 자산 참조 0개, 세 시드에서 원본/번들 엔진의 미리보기·행동 결과·진행 상태 일치를 확인했다. 직접 `file:` 브라우저 검증의 기존 한계는 유지된다.
- 새 규칙의 훈련과 미사용 검증 수치, 배치별 통제 비교는 [BALANCE.md](BALANCE.md)의 최신 절을 기준으로 한다. 이전 450런·상한 직후 60런과 합쳐 현재 승률을 계산하지 않는다.


## 2026-11-17: 보상 주기·역할 분리·다칸 원천 — 규칙 v4

### 변경과 자동 기능 검증

- 관객 후 유물 3택1, 평가 통과 후 조각 3택1, 조각 판매 폐지를 적용했다. 일반 관객·평가 통과·평가 실패·최종 승리의 보상 분기를 구분한다. 유료 조각 요청은 엔진에서 거절하며 자원·후보를 소모하지 않는다.

- 다칸 원천은 점유 칸별 최댓값을 쓰며 전체 외곽에서 하나의 원천으로 전달한다. 2칸 긴 거울은 기본 ×1.01, 두 칸 모두 활성·서로 다른 요구 묶음일 때 ×1.02다. 동일 눈 묶음에서 레벨만 다른 경우에는 보너스가 없다.
- 규칙·화폐·저장 복원 테스트 **64/64개 통과**. 새 사례는 보상 분기, 유료 조각 요청의 원자적 거절, 최댓값과 한 칸 미충족, 다칸 외곽의 전달·중복 접촉, 조건부 배율, 구 저장 상점 정리와 완료 기록 표시를 포함한다.
- 진행 중 구 상점의 유료 조각·일반 관객 조각 보상을 제거하고, 평가 통과 뒤 기존 조각 후보는 재추첨하지 않는다. 완료된 구 저장은 당시 유물 효과와 기록을 보존한다. 새 슬롯은 `strange-museum-run-v4`이며 옛 슬롯은 유지한다.
- `simulate.mjs --self-check` 통과. 표본 ID 8000에서 정책마다 1런씩 실행한 [v4 스모크](balance-v4-smoke.json)는 모두 오류 없이 합법 종료했다. casual/balanced/investor는 각각 2/6/7주차 패배다. casual·balanced에서 긴 거울 획득과 실제 발동을 확인했다. 3런은 전체 균형·승률·인간 난이도 검증이 아니다.

### UI·CLI·단일 HTML 검증

- UI 코드 구문과 CLI 입력/출력 스모크를 확인했다. 생성 마크업에서 일반 관객 뒤 유물 보상만 표시되고 평가 통과 뒤 조각 보상이 추가되며, 유료 조각 영역이 없음을 확인했다. 회전한 긴 거울 점유, 구 v3 완료 저장의 효과 표시, 긴 거울 기본 ×1.01과 조건부 ×1.02 표시도 코드/마크업 스모크로 확인했다.

### 이번에 완료하지 못한 확인

- 실제 브라우저 시각·상호작용 QA는 완료하지 못했다. IAB에서 로컬 URL 연결이 시간 초과됐고, native Chrome CUA는 현재 URL을 확실히 판별할 수 없어 중단됐다. 코드/마크업 스모크를 실제 시각 QA로 표기하지 않는다.
- 별도 HTTP 확인은 샌드박스 소켓 접근 거절 뒤 읽기 전용 재시도에서도 시간 초과됐다. **v4 HTTP 200을 확인했다는 기록은 없다.** 테스트 서버는 종료했다. 원인을 네트워크·보안 설정 문제로 단정하지 않는다.
- 직접 file: 실행, 실제 터치 기기, 인간의 장시간 플레이는 이번 검증 범위에 포함하지 않는다. 이전 버전의 해당 한계도 자동으로 해소된 것이 아니다.


## 2026-11-17: 배율 증가분 합산·공간 자동 검증 — 규칙 v5

- 배율은 `1 + Σ((m−1)×발동 횟수)`다. 거울 2회는 배율 1.02, 동전의 합연산 20에 적용하면 20.4다. 서로 다른 원천·조건부 긴 거울도 기본 1을 공유한다. 발동이 없으면 배율 1, 합연산이 없으면 감동 0이다.
- 완료된 v4 이하 저장은 과거 곱셈으로 보존한다. 진행 중 저장은 v5로 옮기되 이미 얻은 점수·역사·돈·난수는 재작성하지 않는다. 저장 슬롯은 v5, 과거 슬롯을 읽는 순서는 v4·v3·v2·v1이다.
- 전체 테스트 **80/80개 통과**. 배율 예시·여러 원천의 기본값 중복 방지·과거 저장, 정확한 주사위 기대값·눈별 대칭성·편집 주사위, 공간/모양/돈 구분·합법 이동/교체·면적 수지·정적 유물 집계·진단 입력 불변성을 포함한다.
- 자동 배치·이동·교체 판단은 실제 면 배열의 최대 252개 눈 빈도 분포를 정확한 확률로 가중한다. 강화 동률만 독립 고정 시드를 사용한다. 리롤 추정은 정책 전용 Monte Carlo를 유지한다. 실제 게임의 미래 RNG를 읽지 않는다.
- `simulate.mjs --self-check` 통과. 전체 런 결과와 5개 정책 조합의 범위는 [BALANCE.md](BALANCE.md), 사전 계획은 [BALANCE-V5-PLAN.md](BALANCE-V5-PLAN.md)를 따른다.
- 최종 수치 반영 후 `build-standalone.mjs`로 `dist/play.html`을 재생성했다. 시드 20261117의 첫 관객 종료까지 번들 MuseumEngine과 원본 모듈의 모든 행동 결과·상태가 일치했다. 번들 도움말에 배율 증가분 합산 설명을 확인했다.
- 이번 v5 검증은 수치·코드·단일 HTML 번들 검증이다. 브라우저 시각/상호작용 QA와 인간 플레이의 재미·난이도 검증을 새로 수행했다는 뜻은 아니다. v4에서 남은 시각 검증 한계는 위 기록과 같다.
